# 求雨 · Lets-Rain

> **⚠️ 仅供娱乐。**
> 这是一个点击小游戏。页面里所有的"天气变化""雷声""雨声"都是程序根据你的点击实时生成的特效与音效，
> **不代表任何实际气象数据、气象预报、观测结果或任何形式的诉求**，与任何气象机构无关。
> 真实天气信息请以官方气象部门发布为准。

狂点按钮把天从**晴天**点成**强对流**：六个阶段逐级推进，每个阶段都往上叠夸张的特效与音效；
手一停，进度就缓慢回落——但**绝不会退回上一个阶段**。阶段越高风越大，按钮会随风飘动并主动躲开指针。

源码仓库：[github.com/HelloWRC/lets-rain](https://github.com/HelloWRC/lets-rain)
（页面底部与「关于」面板里都有入口）

## 技术栈

| 关注点 | 选择 |
| --- | --- |
| 框架 / 构建 | Vue 3.5（`<script setup>` + TypeScript）+ Vite 7 |
| 包管理器 | **pnpm**（`pnpm-lock.yaml` 是唯一锁文件；请勿使用 npm / yarn） |
| 图形 | CSS 渐变与关键帧 + 单个 Canvas 粒子层（无任何图片资源） |
| 音效 | Web Audio API 实时合成（无任何音频文件、无外部请求） |
| 状态 | 模块级单例 `reactive` store + 类型化事件总线（不引入 Pinia / 路由） |
| 测试 | Vitest（逻辑用 node 环境、组件与持久化用 jsdom） |

运行时依赖只有 `vue` 一个。

## 玩法

1. **狂点中间那颗按钮**推进求雨进度：晴天 → 多云 → 阴天 → 雨 → 暴雨 → 强对流。
2. **连点越快越有效**：连击 8 / 16 / 28 次时增益倍率升档（×1.25 / ×1.5 / ×1.75），
   连击窗口 700ms，停手即归零（历史最高连击会保留）。
3. **停手会缓慢回落**：每个阶段有各自的"闲置回落速度"，进度会从当前阶段的值往 0 掉，
   但**阶段不会倒退**——已经求到的天，跑不掉。进度掉到 0 就停在当前阶段等你继续点。
4. **阶段越高风越大**：按钮按风场飘动，从阴天开始还会主动躲开指针（越到后期躲得越快越远）。
   点不中也没关系：键盘 `Space` / `Enter` 同样有效（限速 160ms/次），鼠标瞄到按钮附近却没点中会记一次"手滑"。
5. **觉得太难**：左侧面板打开「轻松模式」（风力减半、取消躲避、回落减速）；
   底部控制栏可静音 / 调音量 / 减弱特效（降低粒子、关闭震动与频闪）/ 重新开始。
6. 把强对流推满即**求雨圆满**，可以「再求一次」。

### 新手势与声音

浏览器要求音频必须由用户手势启动：第一次点击页面时才会创建 `AudioContext`。
首次访问会有一次提示弹窗，说明"仅供娱乐"与"会播放声音"，也可以勾选"先静音"。

## 阶段设计

数值集中在 `src/game/stages.ts` 一张表里，改难度只改这张表，不需要动逻辑。

| # | 阶段 | 单次增益 | 所需点击<br>(无连击) | 闲置回落/秒 | 风力幅值 | 躲避强度 | 音效增量 | 特效增量 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | 晴天 | 0.150 | 7 | 5% | 7px | 0 | 清脆"叮"声（随连击升调） | 旋转日芒、光晕呼吸、热浪扭曲、浮尘 |
| 1 | 多云 | 0.135 | 8 | 7% | 20px | 0.15 | 木鱼敲击 + 渐强风声 | 分层云漂移、落叶花瓣横飞 |
| 2 | 阴天 | 0.125 | 8 | 9% | 34px | 0.50 | 低沉 drone | 云盖铺满、暗角收紧、**有闪无雷**的远景闪电 |
| 3 | 雨 | 0.115 | 9 | 11% | 52px | 0.75 | 雨声起 + 水滴叮咚 | 雨丝、地面涟漪、屏幕水珠、按钮水花环 |
| 4 | 暴雨 | 0.105 | 10 | 13% | 72px | 0.95 | 雷炸 + 风啸 + 雨墙轰鸣 | 密集雨柱、屏幕震动、近距闪雷、按钮电弧 |
| 5 | 强对流 | 0.095 | 11 | 15% | 100px | 1.00 | 龙卷风啸叫 + 警报 + 冰雹敲击 | 旋转涡流、冰雹弹跳、碎屑飞旋、频闪、色彩偏移 |

**难度相关**（想调手感就改这几个数）：

- **点击次数**：无连击时全程 **53 次**（改版前 37 次）；连击倍率拉满（×1.75）后实测「全速连点」约 **43 次**。
  增益与回落之比从 4.4（晴天）/0.87（强对流）降到 3.0 / 0.63 —— 后期只要手一停，进度掉得比点得还快。
- **按钮位移**：风力幅值 7 → 100px；位移上限（相对视口）横向 44%、纵向 44%；
  躲避触发半径 = 按钮半径 × 2.2~2.6，躲避反应时间 0.30 → 0.15 秒（越小越难追）；
  躲避推力按"椭圆 reach"分配，横竖各用自己的可用范围（否则竖屏手机会被横向的窄空间拖住）。
  手机竖屏实测最大位移 2 → **165px**（纵向为主，因为竖屏竖向空间更大），全程不出界。
- **活动区域**：按钮只会在"去掉顶部阶段轨道、底部数据条/控制栏、左右侧面板"之后的区域里飘动。
  位移调大后如果不做这个约束，按钮会钻到 HUD 下面 —— 那里既被界面盖住又点不到（实测横屏手机会压住数据条）。
- **触屏系数**：触屏躲避强度 ×0.85（鼠标为 ×1.0）；真的想放水就在面板里开「轻松模式」
  （风力减半、彻底关掉躲避、回落减速 20%）。

天空配色、云量、雨量等全部随阶段**连续插值**（约 0.9 秒过渡），不会生硬跳色。

## 三条被测试锁死的核心不变量

1. **阶段永不回退**：回落只作用于"阶段内进度"并被钳制到 0，阶段索引单调不减
   （单测里模拟闲置 5 分钟，阶段不变）。
2. **一次点击不会跨阶段**：进度溢出触发升级时，余量结转被限制在 0.25 以内。
3. **按钮永远可点**：风场位移被限制在视口比例内，按钮整体被夹在安全区内；
   指针正好落在按钮中心时躲避为 0，因此不存在"数学上打不到"的死局
   （单测用 1000 组随机视口/指针/阶段穷举验证）。

## 移动端适配

**布局**

| 断点 | 变化 |
| --- | --- |
| ≤900px（窄屏/横屏手机） | 左侧三张数据卡片收成底部一行紧凑胶囊（连击/诚心/手滑 + 「详情」展开完整卡片）；播报条居中并只留最近 3 条；控制栏按钮放大到 44px 且文案变短以排进一行 |
| ≤720px（手机竖屏） | 按钮 170→132px，内边距收紧；声明条正文 12.5px、按钮排到右侧（不另占一行，整条从 122px 压到 80px） |
| ≤480px 高（手机横屏） | 按钮 104px；阶段轨道只留节点与阶段名；播报挪到右上角只留 1 条；声明条再压一档 |

- 使用 `env(safe-area-inset-*)` 让开刘海与 Home 指示条（`viewport-fit=cover` 已在 `index.html` 声明）。
- 交互元素在竖屏下一律 ≥44px 高；横屏受高度限制为 34~38px（明确取舍）。
- 底部界面（声明条 / 控制栏 / 数据条 / 播报）是**真实布局层**而不是互相覆盖的浮层，
  实测各场景两两重叠面积均为 **0 px²**（含 390×844 与 844×390）。
- 关掉了移动端点击时的系统高亮方块（`-webkit-tap-highlight-color: transparent`）——
  那本身就是一次"闪烁"；按钮统一 `touch-action: manipulation` 防双击缩放。

**移动端自动减弱特效（缓解闪烁）**

触屏优先设备（`(pointer: coarse)` 且 `(hover: none)`）默认自动进入「减弱特效」：

- 粒子数量降到约 42%，并关闭屏幕震动；闪电**主闪频率限制在约 4 次/秒以内**、闪光强度降到 60%、渐变拉长；
- 强对流的**频闪层与按钮电弧直接不渲染**；按钮光环脉冲、云层翻涌等"呼吸式"动画停掉；
- 旋转类特效（日芒、涡流、云层漂移）放慢 3~40 倍；连点时的弱点闪也一并关掉；
- 触屏上按钮躲避强度降为 55%（手指没有 hover，追一颗逃跑的按钮只会让人放弃）。

用户随时可以在控制栏把「特效：自动」点成「特效：关」来看完整特效，这个选择会持久化
（`mobileAutoReduce: false`），之后不再自动接管；桌面端不受影响。

> 判定不用 `navigator.maxTouchPoints`：本机无头浏览器实测它返回 10，会把桌面误判成手机。
> 用"主指针是粗的且不能悬停"才可靠。

**移动端渲染安全模式（与特效档位解耦）**

移动端出现过"界面内容随即变黑、甚至整页变黑"的渲染异常。这不是光效强弱问题，而是 GPU 合成压力 /
合成器（尤其是厂商 WebView）兼容问题。因此**只要判定为触屏设备就无条件降级渲染**，
与"特效档位"完全解耦（档位只管动效强弱）：

| 降级项 | 原因 |
| --- | --- |
| 全部去掉 `backdrop-filter`（毛玻璃） | 部分 WebView 会把它直接画成黑色矩形 |
| 去掉 `mix-blend-mode` | 需要读取背景，合成压力大且兼容性差 |
| 去掉大面积 `filter: blur()`（云层 7px、光环 10px…） | 每层云都模糊一次，图层显存成倍增长 |
| 去掉 `will-change` 强图层提升 | 手机显存吃紧时合成器会丢内容，"黑屏"往往就是这么来的 |
| 去掉云的 `::after` 翻涌伪元素 | 等于把每层云的绘制量与图层数翻倍 |
| 隐藏日芒 / 热浪扭曲 / 屏幕水珠 | 大图层 + 遮罩 + 锥形渐变 + 旋转，收益低代价高 |
| 云层数封顶 4~5 层（原本最多 9 层） | 云是面积最大的合成层 |
| Canvas 分辨率上限从 DPR 2 降到 1.25~1.5 | 手机上 DPR 3 的全屏画布非常吃显存 |
| 风向流线最多 8 条 | 几十个被提升的动画元素代价很高 |

实测（390×844 @2x 触屏模拟）：毛玻璃 `none`、云层模糊 `none`、`will-change: auto`、
混合模式 `normal`、全屏闪光层 `display:none`、云层 ≤4、流线 0、播报 0、按钮光环 1 层；
**89 帧 p50/p95 16.7/16.8ms，零掉帧**（同一无头环境软件渲染下，桌面 1440×900 强对流是 p50 83ms）。

**兜底开关：`?safe=1`**

如果常规降级后仍然出现变黑，可在地址后加 `?safe=1` 打开「渲染安全模式」：
连 Canvas、渐变、模糊、阴影都不渲染，只保留纯色背景 + 按钮 + 界面（可正常游玩）。
`?safe=0` 关闭并持久化。它同时也是一个定位手段：
安全模式下正常说明问题属于合成/GPU 类，仍然异常则另有原因。

## 可访问性与安全

- **界面文字在任何阶段都必须读得出来**。这是本项目踩过的最大的坑：天空配色随阶段从浅金走到近黑，
  而 `--text`（正文色）也跟着在"深藏青"和"近白"之间翻转。任何"半透明深色面板 + 继承 `--text`"的写法
  都必然有一半阶段变成深字压深底（实测旧实现最差 **1.15:1**，几乎看不见）。
  现在所有界面元素统一改用两套**固定**令牌：
  - `--note-*`：三个免责声明界面（首次提示弹窗、常驻页脚条、关于面板）；
  - `--hud-*`：阶段轨道、数据面板、播报、升级横幅、控制栏、求雨按钮周围的浮字。
  最终实测 **131 项文字/背景组合全部达到 WCAG AAA（最低 7.53:1）**，覆盖 6 个阶段、
  桌面 1440×900 与移动 390×844 两种视口。（页脚声明正文 16.88:1、弹窗正文 8.65:1、
  HUD 数值 10.9~15.1:1、求雨按钮主文字 8.0~12.7:1。）
- 为什么会这样：`--text` 的极性是"跟着天空走"的，而面板底色是固定的深色；
  另外闪电会把整屏闪白，浅底深字的面板会瞬间失效，所以固定"深底亮字"更安全。
- 求雨按钮的底色永远是浅色 accent，因此按钮上的文字固定用深色（`--hud-on-accent`），
  旧实现继承 `--text` 时在阴天及之后的四个阶段只有约 1.5~2.2:1。
- 排版上：声明正文 13px（窄屏 12.5px）/ 行高 1.65、弹窗正文 14px / 行高 1.85 并限制行宽、
  「仅供娱乐」做成高对比徽标、关键限制条款加粗提亮、`<mark>` 高亮、交互元素最小 44px 高；
  界面里不使用"靠 opacity 脉冲"来吸引注意（那会在低点把对比度一起压掉，改用外发光）。
- 页脚声明条是 **grid 布局行**而不是覆盖层：底部控制栏等浮动元素都在独立的"舞台区"里，
  声明文字再长、屏幕再窄也不会互相压住（实测重叠 0px，桌面与 390×844 移动端均是）。
- 支持 `Space` / `Enter` 键盘求雨，按钮有可见焦点环；阶段变化用 `aria-live` 播报；
  声明弹窗与关于面板打开时会自动把焦点移入对话框（实测焦点落在对话框本身 / 「关闭」按钮）。
- 遵循 `prefers-reduced-motion`：风力与粒子大幅降低、关闭躲避/震动/频闪；控制栏另有「减弱特效」开关
  （移动端默认自动打开，见上一节）。
- 光敏安全：闪电主闪频率被限制在 3Hz 以下（强对流约 2.4Hz），减弱特效下进一步限频到约 4 次/秒以内并关掉频闪；
  两种途径都能完全关闭闪烁。
- 音效默认开启但会在首次访问时明确告知，随时可静音；音量可在控制栏调节。

  改造后 131 项组合**全部 AAA（最低 7.53:1）**，覆盖 6 个阶段 + 桌面/移动双视口。
