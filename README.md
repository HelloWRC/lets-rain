# 求雨 · Lets-Rain

> **⚠️ 仅供娱乐。**
> 这是一个点击小游戏。页面里所有的"天气变化""雷声""雨声"都是程序根据你的点击实时生成的特效与音效，
> **不代表任何实际气象数据、气象预报、观测结果或任何形式的诉求**，与任何气象机构无关。
> 真实天气信息请以官方气象部门发布为准。

狂点按钮把天从**晴天**点成**强对流**：六个阶段逐级推进，每个阶段都往上叠夸张的特效与音效；
手一停，进度就缓慢回落——但**绝不会退回上一个阶段**。阶段越高风越大，按钮会随风飘动并主动躲开指针。

## 技术栈

| 关注点 | 选择 |
| --- | --- |
| 框架 / 构建 | Vue 3.5（`<script setup>` + TypeScript）+ Vite 7 |
| 包管理器 | **pnpm**（`pnpm-lock.yaml` 是唯一锁文件；请勿使用 npm / yarn） |
| 图形 | CSS 渐变与关键帧 + 单个 Canvas 粒子层（无任何图片资源） |
| 音效 | Web Audio API 实时合成（无任何音频文件、无外部请求） |
| 状态 | 模块级单例 `reactive` store + 类型化事件总线（不引入 Pinia / 路由） |
| 测试 | Vitest（逻辑用 node 环境、组件与持久化用 jsdom） |

运行时依赖只有 `vue` 一个。

## 玩法

1. **狂点中间那颗按钮**推进求雨进度：晴天 → 多云 → 阴天 → 雨 → 暴雨 → 强对流。
2. **连点越快越有效**：连击 8 / 16 / 28 次时增益倍率升档（×1.25 / ×1.5 / ×1.75），
   连击窗口 700ms，停手即归零（历史最高连击会保留）。
3. **停手会缓慢回落**：每个阶段有各自的"闲置回落速度"，进度会从当前阶段的值往 0 掉，
   但**阶段不会倒退**——已经求到的天，跑不掉。进度掉到 0 就停在当前阶段等你继续点。
4. **阶段越高风越大**：按钮按风场飘动，从阴天开始还会主动躲开指针（越到后期躲得越快越远）。
   点不中也没关系：键盘 `Space` / `Enter` 同样有效（限速 160ms/次），鼠标瞄到按钮附近却没点中会记一次"手滑"。
5. **觉得太难**：左侧面板打开「轻松模式」（风力减半、取消躲避、回落减速）；
   底部控制栏可静音 / 调音量 / 减弱特效（降低粒子、关闭震动与频闪）/ 重新开始。
6. 把强对流推满即**求雨圆满**，可以「再求一次」。

### 新手势与声音

浏览器要求音频必须由用户手势启动：第一次点击页面时才会创建 `AudioContext`。
首次访问会有一次提示弹窗，说明"仅供娱乐"与"会播放声音"，也可以勾选"先静音"。

## 阶段设计

数值集中在 `src/game/stages.ts` 一张表里，改难度只改这张表，不需要动逻辑。

| # | 阶段 | 单次增益 | 闲置回落/秒 | 风力幅值 | 躲避强度 | 音效增量 | 特效增量 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | 晴天 | 0.22 | 5% | 4px | 0 | 清脆"叮"声（随连击升调） | 旋转日芒、光晕呼吸、热浪扭曲、浮尘 |
| 1 | 多云 | 0.20 | 7% | 12px | 0 | 木鱼敲击 + 渐强风声 | 分层云漂移、落叶花瓣横飞 |
| 2 | 阴天 | 0.19 | 9% | 20px | 0.35 | 低沉 drone | 云盖铺满、暗角收紧、**有闪无雷**的远景闪电 |
| 3 | 雨 | 0.17 | 11% | 30px | 0.60 | 雨声起 + 水滴叮咚 | 雨丝、地面涟漪、屏幕水珠、按钮水花环 |
| 4 | 暴雨 | 0.15 | 13% | 42px | 0.85 | 雷炸 + 风啸 + 雨墙轰鸣 | 密集雨柱、屏幕震动、近距闪雷、按钮电弧 |
| 5 | 强对流 | 0.13 | 15% | 60px | 1.00 | 龙卷风啸叫 + 警报 + 冰雹敲击 | 旋转涡流、冰雹弹跳、碎屑飞旋、频闪、色彩偏移 |

天空配色、云量、雨量等全部随阶段**连续插值**（约 0.9 秒过渡），不会生硬跳色。

## 三条被测试锁死的核心不变量

1. **阶段永不回退**：回落只作用于"阶段内进度"并被钳制到 0，阶段索引单调不减
   （单测里模拟闲置 5 分钟，阶段不变）。
2. **一次点击不会跨阶段**：进度溢出触发升级时，余量结转被限制在 0.25 以内。
3. **按钮永远可点**：风场位移被限制在视口比例内，按钮整体被夹在安全区内；
   指针正好落在按钮中心时躲避为 0，因此不存在"数学上打不到"的死局
   （单测用 1000 组随机视口/指针/阶段穷举验证）。

## 可访问性与安全

- **界面文字在任何阶段都必须读得出来**。这是本项目踩过的最大的坑：天空配色随阶段从浅金走到近黑，
  而 `--text`（正文色）也跟着在"深藏青"和"近白"之间翻转。任何"半透明深色面板 + 继承 `--text`"的写法
  都必然有一半阶段变成深字压深底（实测旧实现最差 **1.15:1**，几乎看不见）。
  现在所有界面元素统一改用两套**固定**令牌：
  - `--note-*`：三个免责声明界面（首次提示弹窗、常驻页脚条、关于面板）；
  - `--hud-*`：阶段轨道、数据面板、播报、升级横幅、控制栏、求雨按钮周围的浮字。
  最终实测 **131 项文字/背景组合全部达到 WCAG AAA（最低 7.53:1）**，覆盖 6 个阶段、
  桌面 1440×900 与移动 390×844 两种视口。（页脚声明正文 16.88:1、弹窗正文 8.65:1、
  HUD 数值 10.9~15.1:1、求雨按钮主文字 8.0~12.7:1。）
- 为什么会这样：`--text` 的极性是"跟着天空走"的，而面板底色是固定的深色；
  另外闪电会把整屏闪白，浅底深字的面板会瞬间失效，所以固定"深底亮字"更安全。
- 求雨按钮的底色永远是浅色 accent，因此按钮上的文字固定用深色（`--hud-on-accent`），
  旧实现继承 `--text` 时在阴天及之后的四个阶段只有约 1.5~2.2:1。
- 排版上：声明正文 13px（窄屏 12.5px）/ 行高 1.65、弹窗正文 14px / 行高 1.85 并限制行宽、
  「仅供娱乐」做成高对比徽标、关键限制条款加粗提亮、`<mark>` 高亮、交互元素最小 44px 高；
  界面里不使用"靠 opacity 脉冲"来吸引注意（那会在低点把对比度一起压掉，改用外发光）。
- 页脚声明条是 **grid 布局行**而不是覆盖层：底部控制栏等浮动元素都在独立的"舞台区"里，
  声明文字再长、屏幕再窄也不会互相压住（实测重叠 0px，桌面与 390×844 移动端均是）。
- 支持 `Space` / `Enter` 键盘求雨，按钮有可见焦点环；阶段变化用 `aria-live` 播报；
  声明弹窗与关于面板打开时会自动把焦点移入对话框（实测焦点落在对话框本身 / 「关闭」按钮）。
- 遵循 `prefers-reduced-motion`：风力与粒子大幅降低、关闭躲避/震动/频闪；控制栏另有「减弱特效」开关。
- 光敏安全：闪电主闪频率被限制在 3Hz 以下（强对流约 2.4Hz），并可通过上述开关完全关闭。
- 音效默认开启但会在首次访问时明确告知，随时可静音；音量可在控制栏调节。
- 移动端：指针事件驱动（触屏抬手后按钮停止躲避），`touch-action: manipulation` 防止双击缩放。

## 验证情况

- `pnpm typecheck` / `pnpm test:run`（54 项）/ `pnpm build` 全部通过。
- 用无头 Chrome 通过 CDP 做过端到端验证：六个阶段都能用真实指针事件推进、
  各阶段天空配色 / 粒子覆盖 / 风场飘动幅度单调升级、按钮全程未出界、
  闲置 3 秒进度下降但阶段不回退、圆满态正常触发。
- 音频引擎在注入式 AudioContext 模拟器下验证：首次手势前不创建上下文，点击后正确建图，
  点击音 / 环境音 / 雷声（棕噪声 + 声像）/ 冰雹 / 升级号角 / 警报 / 圆满钟声均被合成，页面零异常。
- 免责声明与全部界面文字做了像素级对比度验证（截取文字区域 → 解码 PNG → 取隐藏文字后的真实
  合成背景 → 按 WCAG 公式计算，取样期间冻结动画以免元素飘走）：改造前最差 **1.15:1**；
  改造后 131 项组合**全部 AAA（最低 7.53:1）**，覆盖 6 个阶段 + 桌面/移动双视口。
  同一次测量还发现并修掉了三个真实缺陷：移动端声明条压住控制栏 70px、
  "点一下开启音效"提示条的低点对比度、"求雨按钮"在阴天之后的四个阶段文字只有约 1.5~2.2:1。
- `vite.config.ts` 里有一条针对 Windows 的防御性配置：编辑器原子写入产生的 `.*.tmpdir/`
  临时目录会让 chokidar 抛 EBUSY 并直接崩掉 dev server（本项目开发中真实发生过两次）。
